# Karma — Flutter app

Mobile client for **Karma** (`karma.blackcurrantlabs.com`). It follows the same
architecture as the hedged / service-automation apps. The API contract and
screen inventory come from [`../KARMA_REVERSE_ENGINEERING.md`](../KARMA_REVERSE_ENGINEERING.md).

- **Package:** `karma` · **Flutter:** 3.38.3 (pinned in `.fvmrc`, use `fvm`)
- **Flavors:** `production`, `staging` (Android product flavors + iOS schemes)

---

```bash
fvm flutter run --flavor staging
```

## API client (`api/`)

`api/` is a local package generated by **openapi-generator `dart-dio`** +
json_serializable, the same recipe as the other apps. Karma's backend has no
published spec, so the source is the hand-written
[`swagger/swagger.yaml`](swagger/swagger.yaml), reverse-engineered from the web
client.

```bash
./dart-api-generator.sh     # swagger/swagger.yaml → api/
```

To add or fix an endpoint, edit `swagger/swagger.yaml`, re-run the generator,
then `./generate_code.sh`. Request and query dates are plain `YYYY-MM-DD`
strings. Format them with `date.yyyymmdd()`.

## Architecture

Feature-first. Infra lives in `lib/core`, features in `lib/src/<feature>/`
with `ui/` (pages + `sections/`, `components/`) and `providers/`.

```
lib/
├── main.dart              bootstrap: orientation, error hooks, ProviderScope
├── app.dart               MaterialApp.router, theme + themeMode, text-scale clamp
├── app_config.dart        AppConfig → picks AppEnv by appFlavor
├── env/env.dart           ProductionEnv / StagingEnv (baseUrl, frontendUrl, label)
├── core/
│   ├── constants/         keys.dart (scaffoldMessengerKey), app_constants.dart
│   ├── error/             AppException + ErrorType (unauthorized/forbidden/connection/…)
│   ├── extension/         async_value · context · future · log · datetime · string ·
│   │                      num · color · form · enum · model · snack_bar_type
│   ├── instances/         api_client (Riverpod) · dio_instance · shar_pref
│   ├── interceptors/      token · unauthorized · logging
│   ├── mixins/            validation · action · refreshable
│   └── utils/             cache_for · debounce · app_utils
└── src/
    ├── routes/            app_router (auto_route) · guards/ (auth, admin) · wrappers/
    ├── theme/             app_color (tokens) · app_text_theme · app_theme · providers/
    ├── shared/            components/ (button, card, badge, loader, error, empty,
    │                      snack bar, ring, segmented tabs, logo, page header)
    │                      providers/ (token, user + isAdmin, internet connection)
    ├── splash/            startup_provider (boot sequence) + splash page
    ├── auth/              session_provider (login / forgot / logout / expire) + sign-in UI
    ├── home/              tab shell (bottom nav = web sidebar)
    ├── dashboard/         greeting + glance tiles (reference feature, wired end to end)
    ├── leaves/            providers: leave summary, holidays (UI scaffolded)
    ├── appraisal/ pay_slips/ attendance/   scaffolded tabs
    └── more/              profile (theme, logout, version) + package info
```

### Networking

- `apiProvider` builds one `models.Api` over `DioInstance` (`DioMixin implements Dio`).
- **Auth:** Karma uses a custom `Token: <jwt>` header. `TokenInterceptor` reads
  the token on every request, so login and logout never rebuild Dio.
- **401** from any non-auth endpoint goes through `UnauthorizedInterceptor`,
  then `session.expire()`, which clears the token and routes to sign-in.
  **403** is *not* a logout. Karma returns it for admin-only endpoints.
- `LoggingInterceptor` runs in debug builds only and masks the token.
- The token is stored in the keystore (`flutter_secure_storage`). Theme lives
  in SharedPreferences.

### State: Riverpod 3 (codegen)

```dart
@riverpod
Future<LeaveSummary> leaveSummary(Ref ref) async {
  cacheFor(ref, const Duration(minutes: 5));          // keep 5 min after last listener
  return ref.read(apiProvider).getLeaveApi().getLeaves().guard<LeaveSummary>();
}
```

- `.guard<T>()` unwraps `Response<T>` and converts every failure to an `AppException`.
- `ref.watch(provider).unfold((data) => …, onRetry: …)` handles loader, error and data in one call.
- Mutations go through `ActionMixin.runAction(...)`, which gives a double-tap
  guard plus success and error toasts.
- `'Saved'.toToast()` / `toToast(type: SnackBarType.error)` work from anywhere.

### Routing

```
/splash → /sign-in
/user (AuthGuard) → '' HomeRoute tabs: dashboard · leaves · appraisal · pay-slips · attendance
                  → profile
```

`AuthGuard` restores the token and calls `GET /auth/getRole` once per session.
Offline sends you to `/no-internet` and keeps the session. A rejected token
sends you to sign-in. Use `AdminGuard` on admin-only routes.

### Theme

The web app's shadcn "zinc" tokens, ported 1:1 (`--background`, `--primary`,
`--muted-foreground`, …), in light and dark. Read them with:

```dart
context.colors.mutedForeground
context.text.semibold16     // Inter; the web uses Geist (bundle TTFs to switch)
```

## Adding a feature (recipe)

1. Endpoint missing? Add it to `swagger/swagger.yaml` → `./dart-api-generator.sh`.
2. `lib/src/<feature>/providers/<thing>_provider.dart`: a `@riverpod` provider
   with `.guard<T>()`, plus `cacheFor` where staleness is OK.
3. `lib/src/<feature>/ui/<thing>_page.dart`: `@RoutePage()`, then `unfold`, then
   shared components.
4. Register the route in `app_router.dart` → `./generate_code.sh`.
5. Model presentation (labels, colours) goes in `core/extension/model.dart`.
